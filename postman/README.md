**Collection:** `api_bloxfi.postman_collection.json`

Use this collection for E2E testing. This README is the flow guide; see **TEST_SCRIPTS_REFERENCE.md** for script details.

## Setup

1. **Import** the collection in Postman (File → Import → select `api_bloxfi.postman_collection.json`).
2. **Set collection variables:**
   - `baseUrl` — e.g. `http://localhost:3000` (default).
   - `apiKey` — Bearer token (shared secret). Must match server env `API_KEY`.
   - `requestId` — Auto-generated by the **Pre-request Script** on every request that needs it (Create User, Update KYB, Submit KYB, Create Account, Add Wallet, Create Onramp, Create Offramp, Create High-Value Request). You don’t need to set or change it manually.
   - `networksCoinCode` — For **List networks for coin** (default `USDT`); must pass `coin` or `coinCode` query.
   - `webhookSecret` — For **Webhooks** requests: same value as server `WEBHOOK_SECRET` (HMAC → `X-Webhook-Signature`). Leave empty if you skip webhooks.
   - `palremitProvisionedAccountId` — For Palremit orchestrator webhooks: copy from DB `providerRefs.palremitOrchestrator.provisionedAccountId` after **Create Onramp** or **Create Offramp** (not returned in API responses).
   - `onrampFiatAssetCode` / `offrampCryptoAssetCode` / `offrampCryptoNetwork` — Defaults match the sample **Create Onramp** / **Create Offramp** bodies; change if your bodies differ.

3. **Auto-saved variables** (set by test scripts when you run requests in order):
   - `userId` — from Create Business User
   - `fileId` — from Upload File
   - `accountId` — from Create Account (onramp or offramp)
   - `walletId` — from Add External Wallet
   - `onrampId`, `onrampTxnRef` — from Create Onramp (`txnRef` is used as Palremit `client_reference`)
   - `offrampId`, `offrampTxnRef` — from Create Offramp
   - `highValueRequestId` — from Create High-Value Request

   You can also set these manually from response bodies or the DB if you run requests out of order.

## E2E testing flow

1. **Readiness** (`GET /ready`) — optional; confirms DB + Redis (no auth).
2. **Health check** — confirm API is up under `/api/v1` (no auth).
3. **Create Business User** — `userId` is auto-saved on **201** or **200** (idempotent replay).
4. **Get User** (optional) — verify user.
5. **Update KYB Information** — use a **new** `requestId` in header.
6. **Upload File** — select a PDF/JPEG/PNG (max 10MB); `fileId` is auto-saved.
7. **Attach KYB Documents** — body uses `{{fileId}}` and `{{userId}}`.
8. **Submit KYB Application** — new `requestId`.
9. **Get KYB Status** (optional).
10. **Create Account (onramp)** — new `requestId`; user must be KYB-approved for the rail; `accountId` is auto-saved.
11. **Create Account (offramp)** (optional) — new `requestId`; overwrites `accountId` in variables if successful.
12. **Add External Wallet** — new `requestId`; `walletId` is auto-saved. **Note:** wallet `chain` is now a **string** (e.g. `TRX`, `BSC`, `ETH`), not an enum.
13. **Get Onramp Rates** (optional).
14. **Create Onramp** — body uses `{{userId}}`, `{{accountId}}`, `{{walletId}}`; body `requestId` must match header; new `requestId`; `onrampId` and `onrampTxnRef` are auto-saved. Expect **`AWAITING_FUNDS`** and **`depositInfo`** (Palremit `POST /v1/provisioned-accounts`; user must have **`businessInfo.email`**).
15. **Palremit: deposit.credited (onramp fiat)** — set `webhookSecret` and **`palremitProvisionedAccountId`** (from DB). Pre-request builds the orchestrator payload and sets **`X-Liquidity-Event-Id`** + signature. Then **Get Onramp** triggers crypto withdrawal.
16. **Get Onramp** — after the deposit webhook, may reach **`CRYPTO_PENDING`** / **`COMPLETED`**. **List Onramps** (optional). Optional follow-up: **Palremit: withdrawal.successful (onramp crypto)** when payout completes.
17. **Get Offramp Rates** (optional).
18. **Create Offramp** — includes required `destination.purposeOfPayment` and `platformFee.walletAddress`; new `requestId`; `offrampId` is auto-saved. Expect **`AWAITING_CRYPTO`** and crypto **deposit instructions**.
19. **Palremit: deposit.credited (offramp crypto)** — after user sends crypto (or to simulate), with `webhookSecret`, **`palremitProvisionedAccountId`**, and **`offrampTxnRef`** set.
20. **Get Offramp** — may start fiat payout after **`CRYPTO_CONFIRMED`**. **Cancel Offramp** (optional).
21. **Get Limits** — platform limits.
22. **Get User Limits** — user-effective limits (uses `{{userId}}`).
23. **Create High-Value Request** — body `requestId` must match header; new `requestId`; `highValueRequestId` is auto-saved.
24. **Get High-Value Request** (optional).

**Webhooks:** Set `webhookSecret`; requests use **no** Bearer auth. Palremit orchestrator requests send **`deposit.credited`** / **`withdrawal.successful`** shapes and fresh **`X-Liquidity-Event-Id`** per send (dedupe).

**Important:** Each idempotent POST has a **Pre-request Script** that generates a new UUID and sets `requestId` before the request is sent, so you can run the flow repeatedly without 409 Conflict.

## Auth

The collection uses **Bearer token** auth at the collection level. Set `apiKey` to the same value as server env `API_KEY`. The app sends `Authorization: Bearer {{apiKey}}`. **Health**, **Readiness**, and **Webhooks** requests override auth to **No Auth** (webhooks use HMAC instead).

## File upload

**Upload File** uses `multipart/form-data` with one field: key `file`, type **File**. In Postman: Body → form-data → key `file`, type **File**, then choose a PDF, JPEG, or PNG (max 10MB). After 201, `fileId` is saved automatically for **Attach KYB Documents**.
